# Scores behind Supplementary Tables S1 and S2

From the repository root, run `python code/analysis/verify_supplementary_scores.py`. The verifier uses NumPy and the Python standard library. It reads the two reader CSVs, the archived ScoLAD branch scores and the paired SALAD scores. It checks 180 fixed-threshold operating rows and 30 selected-case score/decision rows without fitting a model or downloading images.

## Inputs and sample identities

- [Paired SALAD scores](salad_operating_scores.csv.gz) has one row per category, seed and relative dataset path. The two columns contain the combined scores for the released-map and regenerated-map implementations. Each seed (42, 43, 44) has 305 normal validation and 1,568 test images. The 5,619 rows thus represent three passes over the same 1,873 images. Open with any gzip-compatible CSV reader.
- Released-map values come from the validation/test pairs used for the operating analysis (`reports/countgd/request21/salad_valtest/seed{seed}/salad_{category}_{val,test}.npz`, archived research revision `ac94014e31fd715b7b2a90077f017c91917a646a`). Regenerated-map values come from the corresponding `salad_full{seed}/scores_path` pairs. Both score columns carry the original `score_combined` values. For each pair, the validation and test dumps recorded the same checkpoint identifiers, normalization constants and RNG setting.
- The older released-map test scores under `results/per_image_scores/salad/` support the headline AUROC comparison but differ slightly from this paired export. Across the 4,704 test entries their maximum absolute difference is about 0.00583. The 30 S2 decisions agree when the archived scores are evaluated at the supplied thresholds. Use the paired file to recover the actual S1/S2 values.
- ScoLAD scores come from `ead_s_seed42_repro` for reconstruction at seed 42, `ead_s` for seeds 43/44, `ead_s_val`, `pc_branch`, and the `hc_tta_merge` test/validation files under `psad_composition`. The composition files provide the row paths. The verifier checks available labels and validation basenames against that ordering. The patch-score files have no independent per-image identifiers.
- S1 fixes a separate threshold per method, category and seed from the normal-validation linear quantile at 95% or 90%. Test alarms require a score strictly above that threshold. S2 uses the same calibration. The script verifies derived scores and decisions. The subtype descriptions are checked for consistency across seeds, not reannotated from images.

## Related revised manuscript tables

[Revision cost and baseline summaries](../tables/revision_costs_and_baselines.json) retains numerical subsets of the authors’ archived research outputs. The SHA-256 hashes identify the original records used to extract the summaries.

|---|---|
| 2 and B2, full CSAD | Average PH+LGST logical and structural AUROCs within each category, average the five categories, then report the mean and sample standard deviation across seeds. All 15 category/seed summary cells are included. [Seed 42 test scores](../tables/csad_ph_lgst_seed42_scores.csv.gz) include relative paths, PH, LGST and their sum for all 1,568 images. Those arrays derive from the authors’ saved three-seed evaluation, research revision `f1421b5e`, directory `reports/countgd/csad3seed/s42/`. For seeds 43 and 44 the companion supplies category-level AUROCs only. |
| B2 and §4.6, regenerated-map SALAD | The paired file above provides complete validation/test scores. Compute each axis AUROC against normal images, then take the equal-weight axis and category means. The three seed values round to 0.9295, 0.9398 and 0.9327. The JSON also contains the archived per-category/seed breakdown. |
| 8 | The JSON supplies per-category/seed medians, the pooled timing statistics for each seed and for the 9,000 repeated measurements, peak allocated/reserved decimal GB and the wall-clock/decode-included rates for all five implementations. The headline median is the mean of category medians, followed by the mean and sample SD across seeds. The pooled median and p95 use the archived 9,000 timings (1,000 distinct images, three repeats and three seeds). Peak memory takes the maximum over categories and seeds. Wall-clock throughput uses timed images divided by total wall time. Decode-included latency averages the three seed-pooled medians; its rate uses reciprocal mean latency, summarized across seeds. This release contains timing summaries rather than individual GPU event traces. |
| 10 | The JSON gives per-category GFLOPs from the GPU forward-counter record plus the analytical patch 1-NN term. Patch combines backbone and nearest-neighbor costs. Composition combines the per-pass segmenter cost times its pass count with one RGB embedding pass. The full cost sums the three branches; the final row averages the five categories equally. |
